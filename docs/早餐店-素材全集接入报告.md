## 2. 切片参数与映射表

### 2.0 共用方法（与上一轮同一套纪律）

1. **不许死板等分**：先逐格求内容包围盒（白阈值 `min(r,g,b) < 235`），再用「相邻内容之间的空隙中点」当真实格线。
   本批 4 张九宫格的格子尺寸有两张不是整数（1024/3 = 341.33），而且**同一列线在不同行可以不同**
   （煎盘手柄、锅的把手都会越过网格线），所以列线是**逐行带内**求的：
   `colCutByRow`（见 `art/_assets_report.json` 各组字段）。
2. **白底 → 透明**（背景不抠）：边界洪泛（`minC ≥ 248`）→ BFS 距离场限制在 ≤3px 外圈 → 覆盖率插值
   → 3×3 加权平滑 → 5×5 中值 → 限量 un-premultiply（单通道 ≤ 20）。
   参数：`NW_BG=248 / T1=236 / UP_MAX=20 / BAND=3`。
3. **同组共用一个缩放系数**（由本组最大内容跨度决定），只缩不拉，组内相对大小保持不变，再居中到方画布。
4. 每个文件都做了非空白校验（不透明占比 / 颜色数 / 平均 α），34/34 通过。

### 2.1 背景 `art/bg/kitchen.png`

源图 2048×1152（1.78:1），画布 1180×790（1.49:1）→ 必须裁。

**木台面上沿的测量**（脚本自动求，不写死）：对每一行算中央带（x 512..1536）的水平梯度能量，取
y ∈ [0.42H, 0.78H] 内的峰值：

```
候选能量峰值：y=653(74.3) y=669(66.2) y=673(78.5) y=674(104.3) y=675(110.1) y=676(66.7)   ← 台面上沿在这里
              y=965..970（另一条强水平边 = 台面前脸的分界）
选中 y=675，其下方 +40px 平均色 rgb(247,174,98) → 暖色木 ✓
```

反解裁切（让台面上沿正好落在画布 `y = 318 = LAY.colHeaderY`，即专属盘带顶部）：

```
scale = (790 − 318) / (1152 − 675) = 0.98952
crop  = 1193 × 798 @ (428, 354)        ← 只存真正会被画到的那块（全图 2.4MB → 861KB）
台面上沿：源 y=675 → 裁切图内 y=321 → 画布 y=317.8（目标 318，误差 0.2px）
比例误差 0.09%（1193/798 = 1.4950 vs 1180/790 = 1.4937）
```

于是 **盘带 328..438 / 锅带 450..608 / 桶带 624..776 三段全部落在木台面上**，顾客卡与顶栏落在街景上。
`breakfast.js` 里保留同一组常量（`BG_IMG.srcSpec/crop/counterTopSrcY/counterTopInCrop/counterTopCanvasY`），
无头断言会**逐字对比**代码常量与 `_assets_report.json`，防止有人手改。

## 6. 顺手修掉的两个「证据链工具」bug（诚实）

出图/无头链用的 `_bf_raster.cjs`（自写软件光栅化器）有两个真 bug，**不修的话本轮出图会骗人**：

1. **9 参 `drawImage` 少看一位**：形参只接住了 `arguments[1..4]`，dest 四元组却写成 `arguments[4..7]`（应为 `[5..8]`）
   → `dw` 被当成 `sh`（背景那张会得到 `dw = 798`），很多情况下直接 `dw <= 0` **静默 return**。
   上一轮游戏只用 5 参，所以一直没暴露；本轮的「背景铺满」「单颗星裁剪」「条前景裁剪」全是 9 参，第一次跑到就翻出来了。
   症状：背景完全不画（画面是纯黑木台），但 `debug.tex().bg` 仍然报 `true`。
2. **解码缓存只按 `img` 对象命中**（`img.__decoded`）：同一个 `Image` 对象换 `src` 时（出图脚本平铺素材就这么干、
   浏览器里也会重新解码）会**复用第一张图的像素** → 整张平铺图 9 格全是同一张图。改成按 `src` 命中；
   出图脚本那边也改成每格新建 `Image`。

两个都修在 `_bf_raster.cjs`（另有一条 `_bf_shots.cjs` 的改动是上一轮留下的，不是本轮）。

## 7. 未接上 / 不满意处（诚实，不含糊）

1. **背景不是整幅构图**：源图 1.78:1、画布 1.49:1，为了让「干净木台面」落在盘/锅/桶带，按 cover 反解裁到
   1193×798 —— **视野只剩源图中段**（源 x 412..1637 / y 332..1152），顶部的灯笼与树冠、最右侧的厨房货架被裁掉了。
   这是任务书允许的「上下裁切或缩放」，但确实不是原图的完整构图。
2. **背景被压暗 32%**（`scrimAll`）：素材是明亮的暖黄木台，压暗后才让金色小字（列头、桶名、图例）读得出来。
   观感比素材原图暗，属于「可读性 > 还原度」的取舍；数值写在 `BG_IMG.scrimAll/scrimTop` 里可调。
3. **耐心条被竖向压缩**：素材条比例约 3.6:1，游戏槽位是 244×22（11:1）→ 竖向压扁约 3 倍，条的立体边框会变细。
   另：三档配色（绿/橙/红）是**半透明色块叠在贴图上**实现的，不是贴图本身变色。
4. **煎蛋盘与培根盘共用 `plate_egg_bacon.png`**（素材一张图里同时有蛋和培根）：为了不「一盘两样」，
   这两种盘不再叠食材贴图 → **盘上分不出具体是蛋还是培根**，只能靠盘下方「煎蛋·热乎 / 培根·温」的文字标签。
5. **糊掉的食物**：矢量画法用深棕色，贴图只能整体压暗（盘位 α=0.55 / 食材 α=0.62），不是逐像素等价。
6. **火候进度环压在锅身上**：厨具贴图铺在灶位框里，进度环仍画在 `cy`（原坐标，没动）→ 环与锅体有重叠，
   我给它加了一圈深色垫底保证可见。属于「位置不动」约束下的视觉妥协。
7. **`tools.png` 只是装饰**：放在操作图例条右端的空位，没有承担交互语义。
8. **木牌 / 红漆按钮的外观无法在本沙箱截图验证**：Chrome/Edge 起不来，DOM+CSS 渲染不了。
   所以这两个按钮只用了「不改变布局」的写法（`background-image` + `background-size:100% 100%` + 不动 border/padding），
   图片缺失时自动退回原按钮。**是否好看我没有证据**，只能保证不出错。
9. **无头 ctx 替身不实现 `translate/scale`**：所以记录下来的 `drawImage` 坐标是**局部坐标**，
   「画在哪个盘位」这类断言改成数「每帧某张贴图画了几次」来验（次数与坐标无关，反而更稳）。
10. **樱花花瓣（矢量）在贴图模式下不再画**（原图本身就有樱花，再叠会脏）；矢量模式下照旧。
11. **顾客头像的「角色」是按顾客编号轮换**（`cid % 3`），与订单内容无关 —— 游戏里的顾客本来就是匿名的（顾客 #1/#2/#3），
    没有「学生就爱点包子」这类设定。
12. **插入的文本块是 LF**，而 `tests/breakfast.test.cjs` 原本是 CRLF（git 配置会自动转换）。功能无影响，但文件里是混合行尾。
13. `_bf_jobs_*.json` / `_bf_new_*.txt`（13 + 13 个）是 `_bf_patch.cjs` 的**补丁输入**，留在仓库根目录作为「每一处改动都是逐字替换」的原始记录；
    如果不需要留档可以整批删掉（不影响任何测试与出图）。
