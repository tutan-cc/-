# 早餐店 · 拼手速 —— 结算出口（#bfGo）与剧情衔接修复报告

> 用户实测反馈：「游戏结束然后呢，都没有找到可以退出游戏的按钮和衔接剧情」
> 结论：**不是"按钮没建、回调没接"，而是"按钮在视口外、点不到"→ 于是唯一的 `onFinish` 触发源永远不触发 → 剧情链自然也不会走。**
> 全部改动：`breakfast.js` / `index.html` / `mahjong.js`(仅 CSS) / `tests/breakfast.test.cjs` / `_e2e_bf_headless.cjs` / `_bf_shots.cjs`(出图)。
> 改动前备份：`index.html.bf5bak`（`index.html` 只用逐字字面替换，无正则、无相对切片）。

---

## 1. 断点根因（指到具体代码行）

### 1.1 为什么"没有退出按钮" —— 布局断点，按钮被裁在视口外

旧代码里**其实有**一个出口按钮：`breakfast.js` 旧 1881 行

```js
'<div class="bf-row"><button type="button" class="bf-btn primary" data-act="close">收 下</button></div>';
...
var cb = panel.querySelector('[data-act="close"]');
if (cb) cb.addEventListener("click", function () { close(true); });
```

它在 DOM 里、监听也挂上了，所以在无头/单测里"点得到"。真实窗口里点不到，是因为三处 CSS 都没有视口兜底（改前）：

| 位置 | 改前 | 问题 |
|---|---|---|
| `index.html` 197 行 | `#bfGame .panel.bf-panel.bf-game-panel{padding:12px 14px 14px}` | 面板没有 `max-height`、没有内滚 |
| `index.html` 209-210 行 | `.bf-result{margin-top:8px;padding:16px 18px;...}` | 结算面板没有 `max-height`、没有内滚 |
| `index.html` 188-190 / 15 行 | `.overlay{position:absolute;inset:0;display:flex;align-items:center;justify-content:center}` + `body{overflow:hidden}` | 覆盖层不滚动，超出的部分**永久裁掉** |

DOM 结构（`index.html` 536 行）：`#bfGameHost` 就是那个 `.panel`，
里面 `.bf-wrap` = `.bf-bar` + `.bf-stage(canvas 1180×790 等比放大)` + `.bf-result`。

1440×900 窗口下的算术：内容宽 = 1180 − 2×14(padding) − 2×1(border) = 1150
→ 画布高 ≈ 790 × 1150/1180 ≈ **770**；加顶栏 ≈ 48、两个 gap 16、结算面板 ≈ 370、面板 padding 26
→ 面板内容总高 ≈ **1230 > 900**。`.overlay` 垂直居中 → 上下各溢出 ≈165px，
而 `.overlay` 不滚动、`body` 又 `overflow:hidden` → **底部那 165px 被裁掉**。
结算面板排在画布下面（y ≈ 850~1220），连同按钮整体落在视口外 ⇒ 玩家看不到、也点不到任何出口。

### 1.2 为什么"没衔接剧情" —— 上面那个断点的下游后果

剧情链在胶水层里**本来是接好的**（改前行号）：

```
index.html 2327  onFinish: function(res){ bfFinish(res); }
index.html 2334  function bfFinish(res){ ... bfApplyResult(res,{story:story}); }
index.html 2273  function bfApplyResult(res,opts){ ... afterInter(res.win?BF_PERFECT.win:BF_PERFECT.lose, ...) }
index.html 1392  function afterInter(fxR,why){ applyFx(...); if(curNode.after.length){ ...playShot() } finishNode(); }
index.html 1398  function finishNode(){ S.done.push(curNode.id); ... render(); }
```

但这整条链**唯一的触发源**是 `onFinish`，而 `onFinish` 只在 `close(true)`（`breakfast.js` 旧 1892 行）里调用，
`close(true)` 只被"那个视口外的按钮"调用。于是：

`按钮在视口外` → `玩家无法调用 close(true)` → `onFinish 永不触发` → `bfRunning/bfNode 永不复位`、`afterInter` 永不执行
→ `S.done` 不含 `sister_bf` → `isAvail("flashback")` 恒 false → **`flashback` 永不解锁**。

即：**剧情没接上 = 1.1 的连锁反应，不是第二个独立 bug**。附带一个认知问题：旧按钮文案是「收 下」，
也没告诉玩家"点了会继续剧情"，这也是用户感觉"没衔接"的原因之一。

### 1.3 顺带查出的真实缺陷（本次一并修掉）

1. `close(true)` **不幂等**（旧 1892 行）：连点 / 重复触发会多次调用 `onFinish`，一次性结算会被重复应用。
2. **没有 ESC 出口**。
3. `dispose()`（旧 1912 行）只取消 rAF + 摘 canvas 监听，**不摘 document 键盘监听**（新增的 ESC 必须清）。
4. **验收脚本自身的 mock bug**（`_e2e_bf_headless.cjs` 旧 127-128 行）：
   `el.className = [].slice.call(set).join(" ")` —— `[].slice.call(Set)` **恒为 `[]`**（Set 不是数组式对象），
   所以 `classList.add()` 等于"把 className 抹成空串"、`contains()` 恒 false。
   过去 187 项里没有一项依赖 classList，所以一直没暴露；本次要断言"覆盖层已关闭 / 宿主 class 已摘"时才发现，已修成 `[...s]`。

## 5. 未完成 / 限制（诚实）

1. **没有真浏览器证据**。本沙箱 Chrome/Edge 起不来（mojo `platform_channel` 被拦）、mshta 落盘被拦。
   所以 `#bfGo` 的"可见"是**三重间接证据**：① `index.html` 真实 CSS 推出的几何不变式（5 档视口断言）
   ② 软件光栅化整屏截图 ③ 真 DOM 节点的存在/点击/清理断言。
   **要 CDP 级 `getBoundingClientRect` 实测**，需要在能起 Chrome 的机器上跑 `_e2e_breakfast.js`
   （已保留 `[data-act=close]` 选择器兼容，并新增了 `__cs2.bfDom().go / .goText`、`__cs2.bfGlue()` 钩子）。
2. 出图里的文字是"软件光栅化 + PowerShell System.Drawing 合成"，不是浏览器渲染；沿用项目既有降级链。
3. 其它玩法只做了"排查 + 全局兜底 + 麻将逐个修"，**没有**给谈判/打斗/躲避/股市/线路/信号/刮彩票逐个加
   `max-height`（避免动到各玩法的布局手感）。它们在极端矮窗口里仍可能需要滚动看完整块面板。
4. 麻将画布本身按宽度等比（`min(94vw,1180px)`），很矮（<790px 高）的窗口里整块 mj UI 仍会超出视口 ——
   现在 `.overlay` 能滚所以够得到，但没做画布高度自适应（属麻将布局，按纪律没动）。
5. `index.html` 的改动全部是逐字字面替换（未用正则/切片），改前备份 `index.html.bf5bak`，每次改完都跑
   `node --check`（内联脚本）+ CSS 括号配平检查。
6. `_bf_shots.cjs` 沿用未固定的 `Math.random`，所以 `bf_game/bf_pass/bf_fail` 每次画面细节会略有浮动；
   `bf_result_exit.png` 的**几何是确定的**（CSS 推导），按钮文案取自当次真跑出的 `#bfGo` 节点。
7. 顺带修的 mock bug（`[].slice.call(Set)`）说明：改前那 187 项里"宿主 class / 覆盖层关闭"这类语义**从未被真正验证过**；
   本次新增的断言是在修好的 mock 上跑的。
